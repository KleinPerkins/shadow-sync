# Existing foreground feedback and deferred Quit recovery

## Authority and scope

This bounded repair implements PRD v3 REQ-SF-05, REQ-GV-06–08/11 and REQ-RL-05/06 within PLAN v3 P2 and P3-CI-01. It restores already asserted behavior in the unpublished extraction candidate. It adds no control, feature, layout, wording, startup registration or repository permission. The application engineer owns the repair; the release engineer owns executable coverage and isolation; the operator owns physical and visual UAT acceptance.

## User journeys and requirements

- UXR-NC-01: After a failed attempt to foreground an ordinary selection, run/report or canonical-root window through the shared dismissal handler, dismissing that same window clears its obsolete menu, tooltip and accessibility-help failure. A separate log-opening error remains visible. Dismissing a different window cannot clear the failure owned by the original window.
- UXR-NC-02: If Quit is requested during a canonical-root authority update, the app waits for the owned update to settle and terminates exactly once. Completion does not reopen the chooser or display a new error alert. An unresolved worker, child, inventory generation, confirmation or transaction continues to block termination.
- UXR-NC-03: Once Quit is pending, another authority update cannot start, including a late callback after the previous update completes. Repeated Quit and duplicate/stale completion callbacks cannot terminate twice or revive admission.
- UXR-NC-04: The separate operation-contention dismissal path retains its current reconciliation contract: dismissing a failed contention window without a valid primary target preserves the published failure; a valid primary target may clear it only after established foreground reality. Existing shortcuts, status-menu copy, inline-error priority, hidden-status guidance, focus behavior and window geometry remain unchanged. Recovery uses the existing invocation and retry paths.

## States and recovery

Loading and disabled states retain the current busy and drain presentation. Empty and ordinary success states have no foreground failure. On failure, the message belongs to the exact foreground target until its existing success/clear path or that target's dismissal retires it. Dismissal preserves unrelated errors and restores the existing shortcut-unavailable help if applicable. A pending Quit is a terminal admission intent; it does not grant authority to bypass unfinished work. Failed verification preserves these defects as open and prevents dependent qualification.

## Accessibility and responsive needs

Tooltip and accessibility help clear together, or return together to the existing shortcut-unavailable text. Keyboard dismissal and existing menu/shortcut routes must exercise the same ownership rule. No new focus movement, animation, colors or layout are introduced. Verify the unchanged native window at minimum supported geometry and a larger desktop geometry, light/dark appearance, keyboard-only dismissal and VoiceOver help. Phone, tablet and web layouts are outside this macOS application scope.
