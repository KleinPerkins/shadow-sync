# MVP signed distribution packaging qualification

Status: implementation qualification only. No product has been submitted to Apple, published, installed or accepted by this record.

## Requirement binding

Implements the notarization and stapling portion of RL-01/RL-02 and the distribution-layout portion of MG-01 under accepted ADR 0008 and the MVP-first PRD/plan. Sparkle and feed promotion remain deferred. The signed lifecycle coordinator still requires installation and migration integration before release qualification.

## Current packaging behavior

`scripts/notarize-release-bundle.py` accepts only an exact source-bound `release-assembly.json` and unchanged Developer ID signed payload. The caller supplies an isolated keychain path, stored notary profile name and signing identity fingerprint. The tool does not read secret values, install the product or publish a release.

An owner-private attempt directory and exclusive lock serialize the transaction. App ZIP and DMG submission IDs, submitted digests and Apple acceptance logs are retained. Unknown upload completion refuses automatic resubmission. Explicit `--resume` accepts only the same source, assembler, packager, publisher and artifact bindings. The submitted DMG remains immutable while its distribution copy is stapled; retries recheck the signed code identity. All signed payload bytes remain unchanged except the exact bounded Apple ticket location, `Contents/CodeResources`.

The app and disk image require accepted notarization, ticket validation, Developer ID verification and Gatekeeper assessment. Final evidence binds source revision/digest, version/build, publisher, submission IDs and distributed artifact digest. A completed package receipt still records publication, installation and product acceptance as false.

## Verification observed

Independent source review identified and resolved post-staple retry, concurrent-resume and root-mode defects. Eighteen synthetic packaging tests pass, including rejected submissions, mismatched logs, changed inputs, interrupted submission bookkeeping, post-staple retry without a second submission, concurrent refusal, signature/Gatekeeper failure and artifact tampering. Eight export tests, seventeen application-CI tests and ten runtime-inventory tests pass.

The nineteen-case native publisher-layout suite passes with complete fixture cleanup. It includes exact ticket preservation through staging and refusal of changed, empty, executable or linked ticket data. This uses a testing build and disposable fixtures; it does not prove Developer ID distribution or installation.

The canonical inventory now contains 110 suites and 1457 cases. This records registration, not a claim that all current-source cases have executed. Hosted application CI remains independently required. The earlier source revision still has a reproducible hosted lifecycle crash awaiting targeted diagnosis.

## Invocation and remaining gates

From the exact checked-out release revision, invoke the tool with `--assembly`, `--output`, `--keychain`, `--notary-profile`, `--signing-identity`, `--source-revision` and `--source-sha256`; pass `--resume` only for a retained attempt. Resolve dependencies before unlocking credentials; the release job owns ephemeral-keychain creation, search-list restoration and cleanup. Never publish private notarization logs without sanitizing them.

Remaining MVP gates are operational required CI and ordinary reviewer-App delivery, integrated source-free installation/migration, actual Apple notarization, immutable candidate publication, downloaded-byte verification, clean installation and preserved-state migration, and focused native/operator acceptance. This record closes none of those gates.
