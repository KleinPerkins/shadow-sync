Implements the notarization and stapling portion of RL-01/RL-02 and the distribution-layout portion of MG-01 under accepted ADR 0008 and the MVP-first PRD/plan. ## Current packaging behavior

`scripts/notarize-release-bundle.py` accepts only an exact source-bound `release-assembly.json` and unchanged Developer ID signed payload. The caller supplies an isolated keychain path, stored notary profile name and signing identity fingerprint. The tool does not read secret values, install the product or publish a release.

An owner-private attempt directory and exclusive lock serialize the transaction. App ZIP and DMG submission IDs, submitted digests and Apple acceptance logs are retained. Unknown upload completion refuses automatic resubmission. Explicit `--resume` accepts only the same source, assembler, packager, publisher and artifact bindings. The submitted DMG remains immutable while its distribution copy is stapled; retries recheck the signed code identity. All signed payload bytes remain unchanged except the exact bounded Apple ticket location, `Contents/CodeResources`.

The app and disk image require accepted notarization, ticket validation, Developer ID verification and Gatekeeper assessment. Final evidence binds source revision/digest, version/build, publisher, submission IDs and distributed artifact digest. A completed package receipt still records publication, installation and product acceptance as false.

The fixture now explicitly matches the producer's required `0755` app root; readiness tests restore their process umask and signal disposition. Production permission checks are unchanged. Eighteen notarization cases pass under each of three umasks (`022`, `027`, `077`), and full tooling discovery passes all 433 cases. Injected packaging-stage failures now require the intended failure message, preventing an earlier refusal from satisfying the wrong test.

The source-free coordinator has a separate bootstrap for self-hosting the existing command custodian. It retains its verified running publisher, exact coordinator executable identity, enclosing distribution resources, and sealed command graph. Filesystem ownership of root-owned distribution bytes remains separate from the non-root calling account. The installed application's canonical-location restriction remains unchanged.

The helper independently permits only fixed service-status and installed-signature observations in this coordinator role. Its parent must be the same exact signed coordinator executable; actual inherited descriptors, durable custody records, admission handshake, and cleanup ownership remain required. The new observation context borrows existing lifecycle-admission locks. It does not add installation or mutation entrypoints, borrow a staged mutation authority, or qualify migration. Testing coordinators refuse production helper authority; bare and malformed helper invocations remain negative fixtures.

Independent review found no actionable defect in this bounded source integration. Exact-source hosted execution and a Developer ID signed positive coordinator-to-custodian transaction, including retained-lock exclusion and drainage, remain required. Installation, staged readiness, legacy migration and recovery integration are still open.
