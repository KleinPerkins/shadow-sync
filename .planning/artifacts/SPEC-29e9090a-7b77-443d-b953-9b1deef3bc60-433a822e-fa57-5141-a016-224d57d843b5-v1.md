# Publisher-verified policy runtime resource contract

## Scope and authority

This technical specification refines ADR 0006 for REQ-SF-02, REQ-SF-04, REQ-SF-05, REQ-SF-06 and REQ-SF-08. It covers production resource authentication, the selected interpreter, suspended-child admission and resource revalidation within the existing 750 ms catalog deadline. Other requirements remain owned by the active phase plan; this specification neither copies deployment policy nor substitutes for migration/update coordination.

The application engineer owns `PublisherPolicyResources.swift`, `PolicyRuntimeLayout.swift`, `PolicyAuthorityFile.swift`, `ClosedProcessRunner.swift`, `PolicyHelperTransport.swift`, `PolicyCatalogSession.swift` and `SelectedRepositoryScope.swift`. The release engineer owns `scripts/build-policy-runtime.py`, sealed runtime manifests, third-party notices and production packaging. Host policy literals and the exact installed AWA deployment remain externally owned. Independent security review is required before source merge.

## Production trust

Use the native Security framework to validate the running canonical per-user application, its static bundle and nested code. Require Developer ID Application, the intended publisher Team ID, hardened runtime, a secure timestamp and the reviewed signing identifiers. Reject ad-hoc signatures, wrong publishers, alternate executable locations, unapproved entitlements and incomplete seals. Verify the currently running dynamic identity as well as the canonical path; path or plist equality alone is insufficient. Offline code-signature checks do not prove current revocation status, notarization, Gatekeeper acceptance or product qualification; release and installed gates establish those separately.

The application seal authenticates adapter bytes, the standalone release contract, the exact AWA contract pin, interpreter-source provenance and the closed runtime-layout manifest before any policy or candidate use. Keep retained identities for the main executable, signature manifest and all resource snapshots. Never derive production authority from a fixture, PATH search, developer-tool launcher, mutable checkout or environment override. A missing or mismatched resource fails closed.

The initial interpreter is the reviewed arm64 CPython 3.14.10 framework payload, repackaged and signed by the application publisher. Its source/package hashes and license inventory remain versioned resources. Current qualification inventory has 795 entries, 85 Mach-O files and 13 reviewed internal links; these counts are release-input evidence, not a permissive pattern or a future compatibility promise. Any runtime update must regenerate and review the exact manifest and rerun packaging, trust, disclosure and performance checks. The AWA classifier remains its independently verified installed module and is never copied into product source.

## Filesystem and process admission

The runtime manifest is closed and bounded. Permit only reviewed relative paths and exact internal framework links. Reject absolute paths, empty/dot/parent components, escapes, unexpected entries, unsupported or fat architectures, writable ownership/mode/ACL combinations, hardlinks and special files. Capture a complete no-follow inventory with device/inode, type, permissions, ACL and change metadata. Retain resource descriptors/snapshots where required; later revalidation must revoke authority after replacement or mutation, including identical-byte replacement. A metadata fast path is permitted only when the retained identity and all mutation-significant fields remain unchanged; it must not skip exact inventory/link checks or trust a new inode.

Spawn the interpreter suspended as an owned, unreaped child. Before allowing its first instruction, authenticate that exact child with the expected Team ID, helper signing identifier and previously verified code hash. A pathname check before spawn alone does not close the replacement race. Failure kills and reaps only the authenticated owned child; no unverified PID signal, lock deletion or fallback execution is permitted. Revalidate resources and the policy snapshot before and after helper execution and at each later admission. Release-bound identity is renewed after a separately coordinated application update.

Typed stdin, descriptor snapshots, complete ordered response correspondence, bounded output, cancellation and owned-child cleanup retain ADR 0006's contract. Only exact validated allow decisions permit candidate access. Lexical prefetch may batch the already authenticated projection roots and prefixes without filesystem inspection, within the existing 64-candidate transport bound and 4096-decision cache bound. Cache entries bind exact candidate bytes and the current resource/policy lease. They never authorize a changed snapshot or later mutation.

## Deadline and failure behavior

The 750 ms aggregate deadline starts before publisher setup; signature/resource verification, policy loading, helper startup, classification, resource revalidation and cleanup count against it. The Continue binder inherits the appropriate bounded operation deadline rather than quietly resetting setup time. Expiry, cancellation, drift or uncertain authority refuses or degrades explicitly, never admits from partial evidence. Do not relax the one-second usable-chooser target or the twenty-trial native acceptance protocol to accommodate verification overhead.

Before readiness commit or repository-sensitive work, an unqualified factory remains fail-closed. Timing from an ad-hoc synthetic framework excludes the real Developer ID chain and cannot qualify the production path. If full publisher setup breaches the limit, record a defect and use a reviewed implementation optimization within this contract; any change to the accepted timing or trust contract requires a governed successor.

## Verification matrix and exit

| Contract | Required verification | Gate |
|---|---|---|
| Publisher and sealed resources | Positive production Developer ID app/helper; wrong Team, identifier, hash, unsigned/ad-hoc, entitlements, timestamp and altered seal refusals; current running/canonical mismatch | Exact signed-artifact evidence, not local ad-hoc fixtures |
| Filesystem lease | Reviewed real topology; changed bytes, same-byte/new-inode replacement, ACL/mode, parent replacement, links, unexpected entries and architecture refusals | All isolated runtime-layout/resource cases pass |
| Suspended child | Correct owned child admits; swapped executable, wrong publisher/hash and lookup failure refuse before execution; cancellation reaps descendants | Native process evidence and no leaked owned resources |
| Policy and data privacy | Resource/policy drift before and after helper; typed request/response and exact AWA release parity; no candidate metadata read before allow | Zero-target-access fixtures; no real protected targets |
| Time and production boundaries | Shared setup deadline, catalog/bind expiry, worst-case inventory, helper count/lifetime, production test-marker exclusion, twenty-trial full signed setup/UI measurements | Source-stage results separate from native minimum-OS and physical UAT |

Source completion requires exact-revision substantive tests, production exclusion checks and independent review. Installed readiness additionally requires the exact external runtime/policy chain, signed application, full production performance, minimum macOS qualification and existing installation/migration gates. No recorded source test, credential-readiness run or document approval closes these latter gates.
