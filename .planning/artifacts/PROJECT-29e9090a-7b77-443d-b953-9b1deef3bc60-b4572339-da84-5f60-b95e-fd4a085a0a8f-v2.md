# ShadowSync project baseline

## Product outcome

Deliver ShadowSync as a standalone, public, proprietary macOS application that can inspect authorized local Git repositories and apply bounded fast-forward-only updates while preserving repository, policy, process, and user-data safety.

## Delivery evidence boundary

The public foundation and ADRs 0001–0004 are merged. Product-source import, operating CI, reviewer App delivery, signed release, installation, migration, update, promotion, retirement, and UAT require their own evidence. This project record defines scope and does not certify those outcomes.

## Intended delivery

- Product and application: ShadowSync / `ShadowSync.app`
- Technical identity: `shadow-sync` / `com.kleinperkins.shadow-sync`
- Repository: public `KleinPerkins/shadow-sync`
- Licensing: proprietary source-visible; third-party terms preserved; binary terms separate
- Initial platform: macOS 26, arm64, deployment target 26.0
- Build baseline: Swift tools 6.2 and Xcode 26.6
- First candidates: `0.10.0` build `15`, then `0.10.1` build `16`

## Product principles

1. Repository selection never grants canonical authority.
2. Preview and session evidence never authorize mutation; every operation freshly revalidates the evidence it uses.
3. Missing or invalid required policy fails closed before repository access.
4. Git mutation remains fast-forward-only.
5. Installation and updates are signed, source-independent, transactional, and recoverable.
6. One active identity, one effective operation authority, and one update authority exist at a time.
7. Public CI is fixture-only; native installed acceptance is separate.
8. Public source, signed release, installation, update, promotion, retirement, and UAT are independently evidenced.

## Scope

In scope:

- sanitized standalone source and public provenance;
- complete active-identity migration with bounded legacy readers;
- repository-owned build, CI, packaging, release, migration, recovery, and update tooling;
- a signed lifecycle coordinator and verified Sparkle updates;
- a repository-specific native hosted-CI/reviewer-App exception;
- consumption of verified external safety policy; and
- preservation of existing safety behavior and open UAT.

Out of scope:

- general interface redesign;
- broader Git repair or cleanup powers;
- copying externally owned protection logic into the product;
- automatic installation of external dependencies;
- Intel, universal, macOS 15, or macOS 27 support;
- source-updater fallback;
- changes to unrelated repositories or fleet policy; and
- treating merge, release, installation, screenshots, or observations as UAT acceptance.

## Authority boundaries

- ShadowSync owns product source, packaging, release metadata, coordinator, and update integration after verified handoff.
- AWA owns generic protection semantics.
- The deployment-policy owner retains concrete policy values and compatibility binding.
- The reviewer App owns ordinary exact-head approval and native auto-merge arming.
- Protected automation and repository administration remain owner/admin controlled.
- The release authority controls signing and publication.
- The operator alone closes UAT explicitly.

## Separate completion states

Track source extraction, repository governance, operational CI, signed release, installed migration, installed update, channel promotion, legacy retirement, and UAT acceptance separately. No state implies another.
