# Deterministic mandatory CI sharding

## Context and scope

The standalone application's mandatory verification includes static checks, compile checks, executable safety suites, native/lifecycle probes and packaging assertions. Its SwiftPM compile target registers zero runtime tests. A successful compile cannot establish runtime coverage. This decision implements the required sharding parity with the reference repositories while keeping macOS 26 arm64 and the native GitHub Actions/App delivery exception unchanged.

Sterling's inspected implementation at `e296721a789586879ed9efd71faec11a41040d15` has canonical test discovery, deterministic partitions, exact coverage receipts and an always-evaluated aggregate. Its checked-in default is one native shard per OS; the [successful current-revision run](https://github.com/KleinPerkins/sterling.io/actions/runs/41511470629) exercised that setting. The [driver](https://github.com/KleinPerkins/sterling.io/blob/e296721a789586879ed9efd71faec11a41040d15/Scripts/ci.py) supports expansion. Other privately inspected reference evidence remains private; no implementation, history or data from it is imported.

## Decision

One versioned registration is the sole authority for logical jobs, ordered executable suites, their actual case rosters, direct argv commands, bounded timeouts and shard counts. Thin developer and CI entrypoints use this registration. The initial logical jobs remain quality, compile-package, runtime-safety, native-and-lifecycle and package-contract. Native jobs run only on standard macOS 26 arm64 runners. Static jobs may use standard Ubuntu runners. Xcode selection, dependency pins, fixture isolation and production-seam exclusion remain mandatory.

Partition stable suite IDs using the first eight bytes of SHA-256, interpreted unsigned big-endian, modulo the configured count. Preserve registered command order within a partition. Start with whole executable suites to preserve fixture ownership and serial lifecycle checks. Every suite must be assigned exactly once in an ordinary run. Empty partitions, duplicate IDs, unknown kinds and unregistered entrypoints refuse planning. Counts are bounded to eight per logical job and selected from measured durations; do not copy another product's numeric count or claim a speedup without measurement. Split a long suite into case-level units only after canonical runtime discovery and fixture independence are proved.

Discover Swift cases through the substantive ShadowSync self-test registry and its observed completion reports, not `swift test`. Discover Python cases through the test framework's canonical IDs. Each test entrypoint and native probe must be registered or explicitly classified as a compatibility alias or manual-only acceptance procedure with an owner and rationale. Source/registry consistency tests reject additions that escape discovery. Full-suite developer execution continues independent suites after a failure and returns nonzero at the end; failures never become successful retries.

All mandatory suites run for every PR, main push and scheduled qualification. This is the initial conservative selection policy: no path filter may omit mandatory coverage. A later audited selective policy requires a successor, protected-base parsing of exact base-to-head changes including both rename paths, always-on core coverage, and widening to the full suite for shared controls, unknown paths or ambiguous input. No selector optimization is authorized by this record.

Routine planning uses trusted base registration bytes and the checked-out exact revision. If the head registration differs, or no predecessor registration exists, transition mode requires all proposed shards plus an independent full unsharded run per logical job. The full run independently executes the canonical suite entrypoint; concatenating shard receipts does not qualify. The aggregate recomputes expected mode and matrix from verified base/head inputs. Invalid base evidence or planning failure is a failing check, never a successful fallback. Changes to registration, runner, workflow or gate use the protected administration path in ADR 0004.

## Evidence and aggregate

Every unit produces its own artifact directory so duplicate extraction cannot overwrite another unit's results. Receipts bind exact checkout revision, tracked-source content digest, run ID, run attempt, registration/plan digest, job, platform/architecture, shard index/count, selected suites, actual executed case IDs, direct-command digest, log/report digest, exit status and cleanup completion. Case reports reject missing, extra, duplicate, skipped and zero-test results. The source digest binds tracked paths, executable modes and contents, refusing symlinks, submodules, unsafe paths and special files.

The static required `ci-required` gate always executes and requires successful planning plus every mandatory logical job. It verifies the exact unit set, deterministic disjoint partition, full union, current source/run identity, evidence hashes and actual case reports. It rejects absent, stale, failed, cancelled, incomplete, malformed or unexpected evidence, including a forged compile result offered as runtime coverage. Transition full-run receipts are additional evidence, not duplicates silently discarded. Native desktop and physical-input UAT remain separate gates wherever hosted probes do not prove behavior.

Use fail-fast false for independent units, bounded parallelism, read-only default tokens, fully pinned actions, explicit timeouts and 14-day sanitized CI artifact retention. Cancel superseded PR runs but do not interpret cancellation as success. Build once per compatible job or qualify exact-byte build reuse with provenance; never share mutable test state or ownership locks between units. Retain wall time, build time, test time and total runner effort separately. Measure cold and warm runs; do not optimize wall time by concealing increased runner effort or reducing coverage.

## Ownership, verification and rollout

The release engineer owns registration, planning, workflows, receipts and aggregate; the application engineer owns executable discovery and fixture independence. The repository administrator owns required-check and protected-path configuration. Independent technical review precedes merge. Ordinary implementation PRs remain reviewer-App controlled; no fleet controller change or rebinding is required.

Qualification must demonstrate deterministic/nonempty/disjoint partitions, complete discovery, exact output rosters, source and report tamper rejection, duplicate/missing units, stale head/attempt, failed/skipped/cancelled jobs, malformed JSON and paths, cleanup failures and transition-mode enforcement. Run every registered unit and the full suite against the same revision, then prove both routine and registration-change hosted paths. Operational completion requires successful hosted receipts and exact-head App delivery, not only source merge or synthetic gate tests.

Rollback reduces scheduling to one full registered unit per logical job through the protected path. It does not disable tests, the aggregate, source binding, fixture isolation or cleanup checks. Preserve failed evidence. This ADR approves requirements and architecture, not implementation completion, installation, release, or UAT.
