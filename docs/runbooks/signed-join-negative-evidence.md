# Signed join negative evidence

The five fixed `signed-installation/start-adapter-join/` controls (`fault-before-bind`, `fault-after-ack`, `fault-before-join`, `fault-after-refusal`, `h-expiry`) are failed fixture subjects. Their original guardian terminal is failed and their original coordinator exits 1. Only a separate read-only assessment can qualify the selected negative row. It cannot qualify an ordinary positive or the unavailable pending-command-retirement requirement.

The source driver uses original owners and unchanged absolute deadlines. Four private one-use assertion certificates are constructed only after actual cut prerequisites. The H control records both real semaphore timeout returns and retrieves both actual typed failed work values. Readiness errors overriding the invocation timeout are ineligible. The before-join result is the measured union of cleanup-only removal and uncertain join refusal. Only the latter and after-refusal can reach the unchanged exact uncertain-disposal preflight. Physical cleanup never repairs failed issuance.

All original joins, checked resource closure, reservation accounting, preparation-retirement ledgers, readiness/endpoint closure and root finish must return before the report is emitted. The sentinel or H subject failure is then rethrown through the ordinary session and guardian. There is no expected-success guardian mode.

## Report wire

Exactly one canonical sorted compact UTF-8 JSON line is emitted on existing stderr with prefix `SIGNED_JOIN_CONTROL_V1 ` and LF. The complete line is at most 4096 bytes. Unknown or duplicate keys, nonfinite values, integer overflow, incorrect array length, unknown enum/mask bits, missing values, extra lines and unexpected output are rejected. The exact fields and every array position are defined in `validate_report()` in `scripts/signed-fixture-negative-report.py`; `serialize_report()` is its matching offline encoder. Swift serialization and nonblocking writes still need native verification.

The deadlines are `[C,H,work,TERM,KILL,receipt,effectiveReceipt,operation,cap]`, with H always C minus three seconds and the selected cap always the minimum original effective receipt and operation. Before-bind has seven null selected-command deadlines and a null command. `holds` has separate real entry, return, result and first explicit release times for adapter and invocation. Result 1 is signalled and 2 is timed out. The emergency bit stays set after H failure. Trace overflow is independently disqualifying.

The command identity mask has exactly ten bits for original context, root, controller, channel, request, handle, record, resource, ticket and helper equality. Product ledger bits represent checked closure, exact removal, issuance, seal and delivered publication. Outcome-specific combinations are closed: no-command has zero bits, cleanup-only has closure/removal only, uncertain disposal has zero product-ledger bits, and ordinary in-budget completion has all five. The cleanup mask binds returned root finish, original work join, service join, readiness join, endpoint closure, original helper retirement and exact empty accounting. All are checked before setting its fixed value.

Negative durable evidence has the original control, catalog and journal hashes, compared to unchanged actual bytes before serialization. The five evidence proof bits are row-applicable checks for unchanged durable bytes, token/collector/readiness refusal, preserved exclusion, stable aliases/live request and no unexpected error. Before-bind and after-ack have empty negative durable hashes and the same mask denotes their applicable absence or successful original-publication checks. Event masks are 0 (no expiry events), 3 (beforeRead/afterRead in that order) or 15 (those events followed by checkedClose/removed). Full object identities and snapshots remain source-side prerequisites, not serialized capabilities.

## Caller contract and read-only assessment

An actual signed caller is a separate prerequisite. For these five IDs it must prepare the child's existing stderr pipe write end as writable and nonblocking **before spawn**. Source preflight checks descriptor type, access mode and O_NONBLOCK before creating the guardian or root. The source never changes descriptor flags. Raw partial writes, EINTR/EAGAIN and poll all remain bounded by original C. A failed, partial or late write never qualifies.

The evaluator consumes a separately pinned `shadow-sync-signed-negative-input/v1` envelope containing `expected`, `artifacts` and `source_root`. `expected` pins case, package SHA-256, source-map SHA-256 and the reviewed caller-source SHA-256. The artifact roster is exactly request, source_map, registration, package, executable, app, caller, guardian, status, stdout and stderr. Each file reference has exactly absolute path, SHA-256, size and POSIX mode. The CLI reads regular current-user-owned single-link files, checks stable identity before/after each read and verifies the full source inventory. It does not import the candidate or perform a native action.

The original caller receipt uses the closed `shadow-sync-signed-negative-caller/v1` fields in `CALLER_KEYS`. It binds original request/root, source, executable/app, sealed package/discovery, transaction and command digest, original cap tuple, pre-spawn pipe preparation and monotonic spawn/report/reap/finish times. It records raw stream digests, actual coordinator exit/reap, all EOF and checked closure, and all transport/deadline/interruption/termination/cleanup errors. The `guardian` artifact is the original guardian stream; this closed profile requires status and stdout empty. A future caller using another status channel must undergo exact contract review rather than silently omitting its data or substituting this schema.

The original caller must emit that receipt honestly from its own observations. A hash or evaluator result does not establish that the caller was reviewed, executed, authenticated, or reaped a real process. The complete guardian stream is reparsed with the unchanged GuardianProtocol. Valid failed evidence requires assertion cancellation, one begun case, zero passed cases, one matching failed completion, matching final custody counts and exit 1. Missing final custody/terminal evidence remains pending or failed. Every input byte is retained unchanged; the only output is a new `shadow-sync-signed-negative-assessment/v1` JSON value on stdout, including raw hashes and exact covered row.

Actual caller binding, supported-host builds, binary exclusion/presence checks, source-bound signed runs and original creator namespace handback remain separate gates. Offline tests use synthetic sealed evidence and cannot supply those gates. Root namespace disposal still belongs to the original creator after coordinator reap.
